# Паспорт проекта Autonotes

Лабораторная работа № 1 «Запуск проекта», БПИ2304. Дата: 23 ноября 2026 года. Ветка: `lab-1`. Здесь описаны проект, его запуск и план на семестр.

## Название и происхождение

Autonotes — наш собственный проект для создания конспектов из фотографий лекционных материалов. [Командный репозиторий](https://github.com/dmice9/Autonotes) технически является форком [IWKMS99/Autonotes](https://github.com/IWKMS99/Autonotes).

Подготовку ЛР № 1 начали с коммита `083bf59988fac752183e779dbba330fdc9e90132`. История проекта сохранена.

## Назначение и решаемая проблема

Студент фотографирует лекционную доску или слайд, но затем вынужден вручную переписывать и сокращать материал. Autonotes сохраняет фотографии, распознаёт текст и формирует краткое содержание. Результат доступен владельцу в личном списке конспектов.

Три основные функции: создание конспекта по одному или нескольким изображениям; получение распознанного текста и краткого содержания; просмотр и удаление собственных конспектов.

## Пользователи и граница системы

Целевые пользователи — студенты и другие слушатели лекций. Подтверждённая прикладная роль — зарегистрированный пользователь: управляет только собственными конспектами и просматривает собственный профиль. Неавторизованный посетитель регистрируется или входит.

В `Role.java` есть `ROLE_ADMIN`, но отдельный административный интерфейс не проверен. Для курса предлагаем вариант «пользователь и внешняя система»: Ollama запускается отдельно и вызывается по HTTP. Эту границу согласуем с преподавателем.

## Предметные сущности

| Сущность | Реализация | Основные данные и связи |
|---|---|---|
| Пользователь | `User`, таблица `users` | Логин, email, хеш пароля, роли, дата создания; владеет конспектами |
| Конспект | `LectureNote`, `lecture_notes` | Название, владелец, состояние, OCR, краткое содержание, даты; содержит изображения |
| Изображение конспекта | `NoteImage`, `note_images` | Путь в MinIO, исходное имя, размер, порядок, ссылка на конспект |

Связи: пользователь 1:N конспект; конспект 1:N изображение. `OutboxEvent` — техническая сущность надёжной доставки, а не дополнительный объект предметной области. Роль и состояние являются перечислениями/классификацией.

Состояния конспекта: `PROCESSING`, затем `COMPLETED` или `FAILED`. Удаление мягкое через `deleted_at`; позднее служебная очистка удаляет данные по политике хранения.

### Поток данных

1. Браузер отправляет multipart-запрос через Nginx в backend.
2. Backend сохраняет файлы в MinIO, а конспект, изображения и событие Outbox — в PostgreSQL. При ошибках предусмотрена компенсация загрузок.
3. `OutboxPublisherService` отправляет задание через RabbitMQ в `notes.process.queue`. Доставка заявлена как at-least-once: повтор возможен.
4. ML получает изображения из MinIO, выполняет OCR и суммаризацию через Ollama, публикует результат с ключом `notes.completed`.
5. `NoteResultConsumer` и `NoteService.processCompletion` сохраняют результат. Повторный результат для уже завершённого конспекта игнорируется.
6. Frontend опрашивает детали конспекта каждые пять секунд, пока состояние равно `PROCESSING`.

### Хранение и конфигурация

PostgreSQL хранит учётные записи, метаданные и результаты, MinIO — бинарные изображения; RabbitMQ передаёт задания и результаты. Docker volumes сохраняют данные между перезапусками. Файл `.env` локальный и исключён из git; шаблон `.env.example` версионируется. Compose передаёт переменные компонентам, Spring использует `application*.yml/properties`, Python — `Settings`, frontend получает URL во время сборки. Токены и настоящие секреты в отчёты не включаются.

| Функция | Реализация | Ручная проверка |

| Распознанный текст | ML `pipeline/note_processor.py`, `llm/ollama_client.py` | Дождаться завершения и сравнить ключевые слова с фотографией |
| Краткое содержание | ML `_summarize`, `pipeline/prompts.py` | Проверить содержание и отсутствие сообщения об ошибке вместо результата |
| Список конспектов | `NoteController.getAllNotes`; frontend `useDashboardNotes`, `noteApi.js` | Найти созданный конспект в своём списке |
| Детали и состояние | `getNoteById`; frontend `useNoteDetail.js` | Проверить `PROCESSING` → итоговое состояние и повторное открытие |
| Удаление | `deleteNote`, JPA soft delete; frontend `useNoteDetail` | Удалить собственную запись; повторное чтение даёт 404 |

Это девять пользовательских функций, ещё без идентификаторов требований ЛР № 2. OCR и суммаризация являются пользовательскими результатами одного асинхронного процесса.
